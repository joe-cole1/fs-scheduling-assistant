Package 0.5.4 simplifies release publishing for maintainers. **Actions → Publish release** now accepts a blank version field. When left blank, the workflow reads the latest published stable release and increments only the patch component by `0.0.1` (for example, `0.5.3` becomes `0.5.4`). A manually entered stable version still overrides automatic selection.

All release-safety behavior is preserved: publication runs are serialized to prevent version races; the workflow validates the current default-branch commit, builds and checks the Word packages twice, generates release notes, creates or resumes a matching draft release, uploads and verifies every asset, and only then publishes the release. A failed blank-version run can be rerun blank and will resolve to the same patch version until that release is successfully published.

There are no scheduling-policy, authority, operator-guide, Local Guidance, or weekly-folder changes in 0.5.4. Existing installations do not need to update solely because of this maintainer automation change. If an installation adopts the 0.5.4 System package for version consistency, use the normal next-week update process and preserve Local Guidance and weekly work.
