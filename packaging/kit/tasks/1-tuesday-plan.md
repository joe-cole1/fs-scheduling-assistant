=== PART 2: THIS TASK - 1 TUESDAY - PLAN NEXT WEEK ===

PURPOSE
Start next week's planning: check the input products, run the first regulation checks, and build the planning picture schedulers need BEFORE they build the lineup. Work status: 1 PRODUCT GATHERING. Do not build a lineup.

WHEN TO USE
- First Tuesday chat of the week: there is no WEEK FILE yet. You will create WEEK FILE 01.
- Again later (new inputs arrived, more planning needed): the user drags in the newest WEEK FILE. Keep its week and update it.

FILES THIS TASK NEEDS
- Always: this task file and SQUADRON RULES.
- Re-runs: the newest WEEK FILE.
- Everything in this week's Inputs folder: the products on the INPUT CHECKLIST, such as DO priorities, the Flight Commander inputs, the upgrade and currency trackers, the Letter of Xs and roster, leave and commitments, the maintenance plan, sims, support, weather and the phase plan.
- If available: last week's schedule or actual duty times, for duty checks across the weekend.

STEP-BY-STEP SCRIPT (6 steps)

Step 1 of 6: Files and week
Do the FILE CHECK (Part 1, section 4).
- First run: state the execution week you will plan (the next Sunday-Saturday week, unless the files clearly show another).
- Re-run: state the week recorded in the WEEK FILE.
YOUR NEXT STEP: "Check the week dates above. If they are right, open this week's Inputs folder, press Ctrl+A to select every file, and drag them all into this chat. If the chat won't take them all at once, drag them in a few at a time." Then type: done. If the dates are wrong, type the correct Sunday date instead.
If input files were already dragged in with the first message, skip asking for them and go straight to Step 2.

Step 2 of 6: Inputs check
For each INPUT CHECKLIST category, say in plain words: Received (file name), Missing, or Problem.
- Give each received product its status (CURRENT / STALE / PARTIAL / CONFLICTED / INTEGRITY FAILED / UNREADABLE / SUPERSEDED). Apply the integrity check to calculated trackers and exports before using any person's values.
- Show only conflicts, gaps, integrity failures and low-confidence readings (CONFLICTS ONLY), unless the user asks to see everything.
- For each missing or problem item, say which checks it limits and who usually owns it. Missing items never stop the rest of planning.
- Ask the most important blocking question, if there is one. Otherwise go on.
YOUR NEXT STEP: either ask the user to get the most important missing product from its owner and drag it in when it arrives ("Then type: continue to keep going without it for now"), or simply "Type: next".

Step 3 of 6: Regulation checks
Using DoW Policies Beta (GAMECHANGER), find the publication-derived requirements relevant to this week's people and planned activities. Cover:
- currency and qualification for the people in the trackers and the Letter of Xs
- evaluations and checkrides
- syllabus prerequisites for the active upgrades
- crew rest and duty
- any other publication-driven checks the products point to
Create stable P-### entries with every required field and one outcome each. Summarize in plain words:
- how many rules were checked and are OK
- any regulation problems found, each listed
- what couldn't be confirmed, and why
- any regulations that disagree
If GAMECHANGER is off, say so, mark these CANNOT VERIFY, and continue.
YOUR NEXT STEP: "Type: next".

Step 4 of 6: Planning picture
Lead with the priorities. Cover all of these, citing sources:
- Checkrides and evaluations: the documented due date or window, prerequisites, evaluator availability, future leave or TDY. Keep the documented due date separate from a recommended earlier window.
- DV or senior-leader flyers: only those explicitly directed in the inputs. Never infer a flying requirement from rank, title or a visit.
- Every active upgradee:
  - next legal event(s) and prerequisites
  - countable-event pace against the Squadron Rules weekly ceiling
  - instructor and resource demand
  - candidate days and windows
  - backup opportunities
  - risk
- Major constraints schedulers must build around: aircraft and configuration (turn pattern, primary lines by go, protected spares, phase/configuration transitions), simulators, range, airspace, tanker and support windows, weather, and personnel availability (tentative leave counts as unavailable).
- 30-day outlook: On track / Watch / At risk for each upgradee.
- One moderate downside case for the week (S-001, or reassess the existing one).
- Anything the DO should decide or direct before the build.
No complete lineup. Schedulers decide when drafting starts.
YOUR NEXT STEP: "Read the priorities above. Type a question if you have one, or type: next".

Step 5 of 6: Questions and answers
- Answer the user's planning questions directly with evidence, using only what the files and regulation checks support.
- Show bounded options, never a full lineup.
- List the open questions for owners and the DO, grouped.
Stay on this step until the user types next.
YOUR NEXT STEP: "Ask another question, or type: next to save the week".

Step 6 of 6: Save the WEEK FILE
Produce WEEK FILE 01, or the next number on a re-run, following Part 1 section 7 and Part 3. Set:
- Saved after: "1 TUESDAY - Plan next week"
- Work status: 1 PRODUCT GATHERING
- NEXT TASK: "2 WEDNESDAY - Check my draft - when schedulers have a draft. Run 1 TUESDAY again first if new inputs arrive."
YOUR NEXT STEP: "Click the WEEK FILE download and save it in this week's folder with exactly this name: WEEK FILE 01 - Tue plan.txt" (use the right number). Then type: saved.
After they type saved, finish with: "Tuesday planning is done. Next: when schedulers have a draft, open a NEW chat and use 2 WEDNESDAY - Check my draft. Remember to drag in your newest WEEK FILE."

DONE WHEN
- Priorities, candidate windows and major constraints are clear.
- The first regulation checks are recorded, including anything that couldn't be confirmed.
- The WEEK FILE is saved.
