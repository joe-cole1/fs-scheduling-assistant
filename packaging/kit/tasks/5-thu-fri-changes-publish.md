=== PART 2: THIS TASK - 5 THU-FRI - CHECK CHANGES AND PUBLISH ===

PURPOSE
After the DO buys the schedule, schedulers make the DO's directed changes. You check that they were carried out faithfully and check the knock-on effects. Then you do the final check before publishing, and record the publication once a human confirms it. Work status: 4 POST-BUY/SELL IMPLEMENTATION / FINAL QC / PUBLICATION.

There is NO routine second DO buy. If a direction can't be carried out, or needs a materially different solution, ONLY that issue goes back to the DO for a supplemental decision before publication. Publication is a separate human action.

FILES THIS TASK NEEDS
- This task file, SQUADRON RULES and the newest WEEK FILE (with the recorded Buy/Sell decision).
- The exact presented Buy/Sell schedule.
- The corrected schedule (or the publication candidate).
- Input products changed by the corrections.

STEP-BY-STEP SCRIPT (5 steps)

Step 1 of 5: Files and choice
Do the FILE CHECK (Part 1, section 4).
- If the WEEK FILE shows no recorded DO buy, say so and ask one yes/no question: "The Buy/Sell decision isn't recorded. Do you want 4 THURSDAY - Buy-Sell instead?"
- Name the presented file and the corrected file.
Then show this menu:
  1 = Check the changes the DO directed
  2 = Final check before publishing
  3 = Record the publication
  4 = Record a supplemental DO decision or a human confirmation
YOUR NEXT STEP: "Type 1, 2, 3 or 4."

Step 2 of 5: Check the directed changes (choice 1)
For EVERY D-### direction, show:
- its exact scope
- where it appears in the corrected file
- its disposition: Open / Implemented-QC pending / Verified / Human-confirmed / Blocked / Superseded (only by a recorded human decision)
- the related finding
Label each change DIRECTED CORRECTION or NEW PROPOSAL. Keep new proposals separate and never fold them into the approved schedule.
Then check the downstream effects and the ENTIRE resulting schedule: affected pilots, duties, roles, prerequisites, formations, aircraft, spares, support, backups, displaced training and later events.
- Re-query GAMECHANGER only for rules affected by changed people, roles, events, timing or prerequisites, and keep unaffected entries as they are.
- Final-QC limits apply: fix hard problems and major upgrade risk, and don't reopen routine optimization.
- If a direction is infeasible or needs a materially different solution, say so and give options for a supplemental DO decision.
YOUR NEXT STEP: either "Fix item 1 in your scheduling tool, save the schedule under a new name, drag it in, then type: menu and choose 1" or "Type: menu".

Step 3 of 5: Final check before publishing (choice 2)
Reconcile the ENTIRE exact publication candidate to the Buy/Sell version, its directions and any supplemental DO decisions. Expose every one of these:
- open hard conflicts and implementation errors
- unexplained material differences
- waiver gaps (each waiver needs the DO plus the applicable authority)
- source limits
- regulation problems, items that couldn't be confirmed, and regulations that disagree
Check any regulation-relevant change not already covered. Separate:
- directed corrections
- human-confirmed closures
- accepted unresolved items within authority
- new proposals
- material departures that need a DO decision
Never manufacture a second buy. Give the exact candidate file name and the remaining human actions.
YOUR NEXT STEP: either the most important fix, or "Publish this exact file through your normal process. Then type: menu and choose 3".

Step 4 of 5: Record the publication or a decision (choices 3 and 4)
Choice 3:
- Ask for the exact published file name, the distribution time and who distributed it.
- Record only what the human confirms. Never infer publication from approval or from this command.
- Keep the presented file and the published file separate, and record how the published file reconciles to the Buy/Sell version.
Choice 4:
- Record a supplemental DO decision as its own D-###, in the DO's exact words and scope.
- Record a human confirmation as Human-confirmed with its exact scope. It never turns a missing regulation check into SOURCE-BACKED OK.
- Ask one question if the type or scope is unclear.
YOUR NEXT STEP: "Check the record above. Type: correct, or type the fix. Then type: menu or save".

Step 5 of 5: Save the WEEK FILE
Produce the next WEEK FILE (Part 1 section 7 and Part 3). Set "Saved after" to "5 THU-FRI - Check changes and publish".
- If published: record the published weekly schedule and make it the weekly cumulative comparison. Set NEXT TASK: "6 EXECUTION WEEK - Schedule change - for any change during the execution week. Use this week's folder."
- If not yet published: set NEXT TASK to "5 THU-FRI - Check changes and publish".
YOUR NEXT STEP: "Click the WEEK FILE download and save it in this week's folder with exactly this name: WEEK FILE NN - Publish.txt" (use the right number). Then type: saved.
After they type saved, finish with the next task in plain words.

DONE WHEN
- Every DO direction has a disposition.
- Any material departure has a supplemental DO decision.
- The exact published file and the human's confirmation of distribution are recorded separately from the DO buy.
- The WEEK FILE is saved.
