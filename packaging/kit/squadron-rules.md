# Squadron Rules - Pantons

Drag this file into every scheduling chat together with the task file. It holds the squadron's own rules, one rule per line, grouped by category. The assistant applies every rule in Part 1. Only the DO approves a rule.

- Next change: record what changed, the date and the DO approval here

## How to read a rule

Each rule is one line: an ID, how strict it is, then the rule.

- **Must:** the schedule can't do this without a documented waiver or exception.
- **Ask the DO first:** allowed only with the DO's approval.
- **Prefer:** the assistant suggests it but does not call it a problem.
- **Method:** how we count or judge something. It is not pass or fail by itself.

## How to add or change a rule

1. Save a copy of this file under a new name first.
2. The easy way: open a new chat with the task file RULES - Add or change squadron rules. It asks questions and hands back lines ready to paste.
3. By hand: go to the rule's category in Part 1, copy the last line, paste it below, give it the next number and change the words. Write one rule per line, in plain words. Add why the rule exists and the DO's approval and date.
4. Not approved yet? Put the line in Part 2. The assistant does not apply Part 2.
5. To retire a rule, move its line to Part 3 and add the date and the reason. Never reuse an ID.
6. Record the change at the top of this file.

A squadron rule may be stricter than a regulation. The assistant still looks regulations up in DoW Policies (GAMECHANGER) and flags a squadron rule that seems to go against one. If a rule only repeats a regulation, name the regulation in the rule's why so the assistant can check it.
