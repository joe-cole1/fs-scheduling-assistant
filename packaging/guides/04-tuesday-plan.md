# Tuesday — Plan the week

Use this after **03 Tuesday - Start the Week.docx**. Tuesday planning reconciles the packet and identifies what must drive Wednesday's human schedule build.

Excel, PDFs, readable screenshots, calendar exports and plain-text notes are acceptable. In a continuing chat, upload only new or revised inputs. Do not retype existing squadron products into blank forms.

## Tuesday first pass

Before the schedulers build Wednesday's lineup, answer five questions:

1. **What needs clarification?** Identify missing, conflicting, stale or unreadable inputs and ask only questions that materially affect planning.
2. **Which checkrides/evaluations matter this week?** Use documented due dates, future leave/TDY, prerequisites, qualified evaluators, resources and DO guidance. Distinguish a due date from a recommended earlier window.
3. **Which DV or senior-leader flyers require deliberate placement?** Identify only flyers actually directed or supported by the inputs. Do not infer qualification, priority or a flying requirement from rank/title alone.
4. **How should upgrades be planned?** Identify each upgradee's next legal events, prerequisites, desired weekly pace, completion risk, instructor/resource demand and useful candidate windows. Do not build the complete lineup.
5. **What publication-backed currency or regulatory requirements matter this week?** Use the currency tracker, Letter of Xs, upgrade/evaluation status and planned activities as the person-specific facts. Query **DoW Policies Beta (GAMECHANGER)** for the governing publications and build the initial **Weekly Publication Rule Ledger**. Do not use model memory or ordinary web search to establish the rule.

Also identify major aircraft/configuration, simulator, range, tanker, support, weather and personnel constraints that should shape the build.

For the publication pass, every regulatory rule must identify the retrieved publication number/title plus paragraph, page or other usable locator. Record version/effective/current status when available. Use only these outcomes: **SOURCE-BACKED OK**, **SOURCE-BACKED ISSUE**, **CANNOT VERIFY**, or **SOURCE CONFLICT**. If GAMECHANGER cannot provide a sufficiently traceable applicable publication, make no regulatory determination.

```text
Also identify major aircraft/configuration, simulator, range, tanker, support,

Then run the Tuesday publication-discovery and currency baseline. Use the currency
tracker, Letter of Xs, upgrade/evaluation status and planned activities to identify
which publication-derived currency, qualification, evaluation, prerequisite,
event-credit, crew-rest/duty or recurring-training rules are relevant this week.
For each rule, query DoW Policies Beta (GAMECHANGER). Do NOT use model memory,
generic military knowledge or ordinary web search as regulatory evidence.

Build a Weekly Publication Rule Ledger with stable P-### IDs. For each entry show:
- check and applicability;
- retrieved requirement;
- publication number/title;
- version/effective/current status when available;
- paragraph/page/locator;
- retrieval date/time; and
- SOURCE-BACKED OK, SOURCE-BACKED ISSUE, CANNOT VERIFY or SOURCE CONFLICT.
Check retrieved evidence for supersession/current status, more-specific applicable

If no sufficiently traceable applicable publication is retrieved, mark CANNOT

qualification or priority from rank/title alone. If leadership guidance is
missing, draft questions or PROPOSED guidance for human confirmation. Do not
create the complete weekly lineup; schedulers will build it Wednesday.
```

**Save:** source products in **Inputs** and the planning report, run control, Weekly Publication Rule Ledger and decision record in **Working Record**.
