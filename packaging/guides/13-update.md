# Update for next week

Use the latest numbered update when starting next week's planning. Finish current-week work under the instructions already in use. No automatic updates occur.

The installed package number appears in generated document headers. Use that package number, not Windows file dates, to identify the System release.

## Update an existing setup

1. Download **Update_Existing_Setup.zip** from the same release page as the full packages and extract it into a temporary folder.
2. Read **UPDATE INSTRUCTIONS.docx**.
3. Before starting next week's planning, replace the permanent folder's entire **System** folder with the update's **System** folder and replace **START HERE.docx** with the supplied copy.
4. Keep **Local Guidance**, **COPY THIS FOLDER FOR EACH NEW WEEK**, and every **Week of ...** folder in place. Do not extract a full setup ZIP over an existing setup.
5. If **PERSISTENT MIGRATIONS.docx** is included, review it and merge only explicitly approved persistent changes. Reference-only files never overwrite local guidance automatically.
6. Open the new **03 Tuesday - Start the Week.docx** when starting the next week's chat.

An update does not change a chat already in progress or reinterpret an earlier buy/sell, waiver, publication or daily approval.

## Roll back

At a next-week boundary, download the exact prior release's **Update_Existing_Setup.zip**, verify the package number, and replace only **System** and **START HERE.docx**. Do not roll back Local Guidance, weekly schedules/records, approvals, human-maintained playbook/reference files or approved persistent migrations automatically.

If an urgent rollback occurs during execution week, preserve current schedule versions, decisions, waivers, buy/sell approval, publication and completed actuals exactly. Tell the chat only that the reusable System instructions changed.

Moving from the earlier Markdown setup requires a full setup ZIP once, followed by manual carryover of approved local guidance and weekly work. Downloading an update or rollback grants no new scheduling approval or waiver.
