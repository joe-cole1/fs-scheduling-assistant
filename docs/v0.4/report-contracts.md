# Report contracts — v0.4

Reports are advisory Markdown. Keep BRIEF decision-oriented and omit empty sections. DETAILED supplies the working analysis. A planning question should receive a direct answer with evidence and limitations, not a complete weekly report. Local scheduling rules come from the approved profile and references.

## Common header

Week; phase/task; as-of/timezone; operational or historical test condition/cutoff; active schedule; comparison baseline(s); local profile/playbook versions; material input limitations. Explicitly distinguish schedule approval/publication state from analysis phase.

## Phase-specific outputs

| Phase | Required output |
| --- | --- |
| Product gathering | Existing products/gaps and affected checks; confirmed guidance versus proposed forms; planning answer, priority evidence and windows/resources/prerequisites |
| Initial draft | Leadership summary; hard conflicts; approval needs; ranked exact changes; lines/spares/configurations/formations/backups; upgrade flow/outlook; comparable IP workload; weekly moderate downside; draft change log; questions and playbook candidates |
| Sell | Feasibility and uncertainty; intended outcomes and progress; checkrides/at-risk upgrades; primary-line use and resource/IP capacity; tradeoffs; unresolved items; numbered DO decision requests |
| Corrections/QC | Every sell decision's disposition; exact corrections versus new proposals; downstream and complete-schedule QC; human-confirmed closures; remaining issues/waivers; exact version for DO buy and separate publication record |
| Execution | Completed actuals / remaining firm / conditional; changed facts; exact cascade; immediate per-day and cumulative weekly deltas; outlook/scenario effects; required sign-offs, DO decisions and waiver routing |

## Sell brief — answer these in order

1. **Can this plan work?** Bottom-line feasibility, unresolved checks and human-confirmed items that matter to the decision.
2. **What does it accomplish?** DO priorities, checkrides, upgrades, required pace and 30-day risk; separate firm and conditional opportunities.
3. **What constrains it?** Primary-line utilization, protected spares, IP/resource limits, phase/configuration dependencies and weather-sensitive events.
4. **What are the tradeoffs?** Specific alternatives, displaced training, resilience and the weekly moderate downside case when material.
5. **What must the DO decide?** Exact numbered requests, recommendation, authority/coordination and deadline. These become a record of directions, not formal buy.

## Compact records

| Record | Columns |
| --- | --- |
| Fact | F-ID; normalized fact; status/confidence; filename and location or human statement |
| Recommendation | R-ID; one decision category; current → proposed; alternative; benefit/displacement; full feasibility/limits; authority/coordination/deadline; evidence |
| Decision | D-ID; direction/new proposal/waiver/confirmation; exact substance/authority; scope/time; version/events; disposition/QC link |
| Outlook | Person/program; completed/remaining; planned date; status; raw/capacity-adjusted pace; phase/bottleneck; firm/conditional; best/risk-adjusted date; assumptions |
| Immediate delta | Affected date; signed daily or weekly fallback; event/person/time/mission/resource before → after; approval status |
| Weekly delta | Published weekly version; resulting plan; cumulative departure and progress/priority/timing effect; actual versus proposed |
| Playbook candidate | Stable C-ID; Pending/Approved/Rejected; lesson; evidence/reusable basis; scope/limits/risk; explicit DO decision |

Do not merge an assistant proposal into an approval record. Do not label human-confirmed matters independently verified. Do not claim “all clear” if portions of the packet were unread or checks remain unresolved. Recognize explicit human closure without demanding extra proof. New materially conflicting facts reopen only affected concerns.

The full initial weekly review includes one moderate downside scenario. Carry it forward with its assumptions and ID; reassess when a change matters. Do not impose a new weekly quota of scenarios for every phase or question.
